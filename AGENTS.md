# Руководство по репозиторию

## Структура проекта и организация модулей
- `linux/` содержит основные точки входа для установки и dotfiles, которые копируются в `$HOME`
- Общие Linux-файлы лежат в `linux/common/`
- Клиентские дополнения лежат в `linux/client/{common,desktop,wsl}/`
- Серверная конфигурация лежит в `linux/server/`
- Файлы конкретного профиля хранятся в соответствующих каталогах `home/`, например `linux/client/desktop/home/.zshrc`
- Серверные конфиги вроде SSH лежат в `linux/server/config/`
- В `windows/` находятся Windows-ассеты и setup-скрипты
- Верхнеуровневые `README.md`, `Makefile` и `git_push.sh` служат основными точками входа

## Команды сборки, проверки и разработки
- Для локальной проверки запускайте setup-скрипты напрямую:
- `bash linux/client/desktop/setup.sh`
- `bash linux/client/wsl/setup.sh`
- `bash linux/server/setup.sh`
- В README опубликованы команды удалённого bootstrap-запуска через `wget -qO- ... | bash`
- Если меняете пути или имена файлов, обновляйте и документацию
- `make push` запускает `git_push.sh`, который добавляет все файлы, создаёт коммит и делает force-push в `main`

## Стиль кода и соглашения по именованию
- Основной язык репозитория это shell
- Держите скрипты линейными и разбивайте их короткими секционными комментариями, например `# Docker` или `# /home`
- Предпочитайте POSIX-совместимый синтаксис, потому что в скриптах указан `#!/bin/sh`
- Если нужен Bash-специфичный код, одновременно обновляйте shebang и документацию по использованию
- Следуйте текущему шаблону имён: каталоги в нижнем регистре (`common`, `desktop`, `wsl`, `server`), временные и экспортируемые переменные в верхнем (`TMP_DIR`, `RUNZSH`)

## Руководство по тестированию
- Закоммиченного автоматизированного тестового контура здесь нет
- Проверяйте изменения запуском затронутого `setup.sh` в отдельной VM, контейнере или WSL-инстансе
- Подтверждайте установку пакетов, копирование dotfiles и корректный запуск shell
- Для правок, связанных с SSH, по возможности запускайте `sudo sshd -t` перед перезапуском сервиса
- Шаги ручной проверки фиксируйте в pull request
